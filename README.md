# «Городские легенды»

«Городские легенды» - это интерактивная карта города, на которой каждая точка может хранить историю. Любой пользователь анонимно оставляет легенду, слух, страшилку или интересный факт, привязанный к конкретному месту - двору, дому, перекрёстку или парку.

### Как это работает

Приложение существует в двух режимах. В режиме карты пользователь видит город с живыми метками: чем популярнее история в точке, тем крупнее кружок на карте. Можно кликнуть на любую метку и прочитать, что люди знают об этом месте, - или добавить свою версию. В режиме ленты карта убирается, и остаётся поток историй со всего города, отсортированный по популярности, новизне или близости к пользователю.

Популярность историй определяется сообществом через лайки и дизлайки - без алгоритмов и редакции. Хорошая история поднимается наверх и растёт на карте, слабая - уходит в тень.

### Зачем это нужно

Каждый город наполнен историями, которые нигде не записаны: «в этом подъезде живёт привидение», «здесь в 90-х был лучший джазовый клуб», «на этом перекрёстке нельзя разворачиваться - примета». «Городские легенды» дают этим историям место на карте и голос - анонимно, без регистрации, без цензуры.

# Функциональные требования

## Роли

| Роль | Описание |
|------|----------|
| **Аноним** | Любой посетитель без регистрации. Основной пользователь системы |
| **Администратор** | Авторизованный сотрудник. Управляет жалобами и скрытым контентом |

---

## Функциональные требования по ролям

### Аноним

#### Карта
- Открывает интерактивную карту города при входе в приложение
- Видит маркеры точек с историями; размер маркера пропорционален суммарному рейтингу историй в точке
- Перемещается по карте, масштабирует её
- Ищет место по адресу через строку поиска
- Кликает на маркер — видит список историй, привязанных к этой точке
- Включает геолокацию, чтобы центрировать карту на своём местоположении

#### Добавление истории
- Кликает на любую точку карты или использует кнопку «Добавить рядом» (по геолокации)
- Вводит текст истории: минимум 20, максимум 2000 символов
- Опционально выбирает категорию: `слух`, `страшилка`, `исторический факт`, `примета`
- Публикует историю без регистрации и email
- Не может публиковать чаще одной истории в 5 минут с одной сессии (защита от спама)

#### Лента
- Переключается в режим ленты — поток карточек без карты
- Выбирает сортировку: по новизне, по популярности, по близости (если геолокация доступна)
- Видит в карточке: текст, адрес точки, категорию, рейтинг, дату публикации
- Кликает на карточку в ленте — карта центрируется на соответствующей точке

#### Голосование
- Ставит лайк или дизлайк под любой историей
- Не может проголосовать за одну историю дважды в рамках одной сессии
- Может сменить голос: лайк -> дизлайк и обратно (переключение, не повтор)
- Не может голосовать за собственную историю в рамках той же сессии

#### Жалобы
- Нажимает «Пожаловаться» под любой историей
- Не может пожаловаться на одну историю дважды с одной сессии
- Не видит содержимого скрытых историй

---

### Администратор

#### Авторизация
- Входит в административную панель по логину и паролю (отдельная страница `/admin`)
- Сессия администратора не пересекается с анонимной сессией пользователя

#### Модерация
- Видит список историй, автоматически скрытых по порогу жалоб
- Для каждой скрытой истории может:
  - **Восстановить** — история возвращается на карту и в ленту, счётчик жалоб обнуляется
  - **Удалить навсегда** — история удаляется из базы данных
- Видит количество жалоб и текст каждой скрытой истории
- Может скрыть или удалить любую историю вручную, не дожидаясь порога жалоб

#### Настройки системы
- Устанавливает порог жалоб для автоскрытия (по умолчанию: 5 жалоб)

## Use Cases

### UC-01 — Читает легенды рядом с собой

**Актор:** Аноним
**Предусловие:** Пользователь открыл приложение, геолокация доступна

1. Приложение запрашивает геолокацию, карта центрируется на текущем положении
2. Пользователь видит маркеры поблизости
3. Кликает на ближайший крупный маркер
4. Читает список историй точки
5. Ставит лайк понравившейся истории

**Альтернатива:** геолокация недоступна -> карта показывает город целиком, пользователь ищет место вручную

---

### UC-02 — Добавляет историю

**Актор:** Аноним

1. Кликает на нужную точку карты
2. В открывшейся панели нажимает «Добавить историю»
3. Вводит текст, выбирает категорию
4. Нажимает «Опубликовать»
5. История появляется на карте; если в точке ещё не было историй — создаётся новый маркер

**Исключения:**
- Текст короче 20 символов -> форма показывает ошибку, история не публикуется
- Прошло менее 5 минут с прошлой публикации -> сообщение «Подождите перед следующей публикацией»

---

### UC-03 — Жалуется на историю

**Актор:** Аноним

1. Нажимает «Пожаловаться» под историей
2. Система фиксирует жалобу, привязывает к сессии
3. Кнопка становится неактивной для этой истории
4. Если жалоб достигло порога -> история автоматически скрывается с карты и из ленты и уходит на модерацию

---

### UC-04 — Администратор модерирует контент

**Актор:** Администратор

1. Администратор входит в `/admin` по логину и паролю
2. Видит очередь скрытых историй с текстом, счётчиком жалоб, датой и адресом
3. Читает историю, принимает решение:
   - Восстанавливает -> история возвращается, жалобы сбрасываются
   - Удаляет -> история исчезает навсегда
4. Переходит к следующей истории в очереди

---

### UC-05 — Просматривает ленту и находит интересное

**Актор:** Аноним

1. Переключается в режим ленты
2. Выбирает сортировку «по популярности»
3. Листает карточки, читает истории
4. Кликает на карточку — карта переключается в режим карты и центрируется на точке истории
5. Исследует соседние маркеры

# Технологический стек

### Фронтенд

- **HTML5** - семантическая разметка: `<header>`, `<main>`, `<nav>`, `<article>`, `<footer>`, `<section>`
- **Vanilla JavaScript (ES6+)** - без фреймворков; fetch API для запросов к серверу, работа с DOM напрямую
- **Leaflet.js** - карта на базе OpenStreetMap, подключается одним `<script>` тегом, весит ~40 КБ, не требует сборщика
- **CSS3** - адаптивная вёрстка через Flexbox и Grid, media-запросы для мобильных, CSS-переменные для темы

### Бэкенд

- **PHP 8.x** - серверная логика, REST-like API (обработка GET/POST запросов, возврат JSON)
- **MySQL** - база данных: таблицы историй, голосов, жалоб; пространственный тип `POINT` + индекс для геозапросов
- **Apache / Nginx** - веб-сервер

### Хранение состояния на клиенте

- `localStorage` - последняя позиция карты (город, zoom, координаты), настройка сортировки ленты
- Session cookie (PHP `session_start()`) - анонимная сессия для учёта голосов без привязки к личности

### Карты и геокодирование

- **Leaflet.js + OpenStreetMap** - бесплатные тайлы без лимитов API
- **Nominatim API** - бесплатный геокодер OSM: адрес -> координаты (поиск по городу)

# Анализ функциональных возможностей «Городские легенды»

## 1. Интерактивная карта

Основной режим взаимодействия с приложением. Пользователь видит карту города с визуальными маркерами, отражающими концентрацию и популярность историй в конкретных точках.

**Ключевые возможности:**
- Отображение маркеров с динамическим размером (зависит от рейтинга историй)
- Зум и перемещение по карте
- Поиск по адресу через Nominatim API
- Клик по маркеру -> список историй точки
- Добавление истории через клик на карте или геолокацию

## 2. Добавление историй

Механизм публикации контента без какого-либо барьера входа - ни регистрации, ни email.

**Ключевые возможности:**
- Привязка текста к географической точке
- Ввод текста до 2000 символов
- Выбор категории: слух, страшилка, исторический факт, примета
- Полная анонимность

## 3. Лента историй

Альтернативный режим просмотра - поток карточек без карты, ориентированный на чтение.

**Ключевые возможности:**
- Сортировка по новизне, популярности, близости к пользователю
- Карточки с текстом, местом, категорией, лайками, датой

## 4. Система голосования

Краудсорсинговая модерация через лайки и дизлайки. Рейтинг влияет на видимость в ленте и размер маркера на карте.

**Ключевые возможности:**
- Лайк / дизлайк под каждой историей
- Защита от повторного голосования через анонимную сессию
- Рейтинг как единственный алгоритм ранжирования

## 5. Система жалоб и модерация

Механизм защиты от нежелательного контента без ручной pre-модерации каждой публикации.

**Ключевые возможности:**
- Кнопка «пожаловаться» на любую историю
- Автоматическое скрытие при достижении порога жалоб
- Административная страница для ручной проверки скрытых историй

## Приоритизация реализации

| Приоритет | Функциональность | Обоснование |
|:---------:|------------------|-------------|
| **1** | Интерактивная карта с маркерами | Ядро продукта - без карты приложение теряет смысл |
| **2** | Добавление истории | Без пользовательского контента карта пуста |
| **3** | Просмотр историй по точке | Базовое чтение - минимально жизнеспособный продукт |
| **4** | Система голосования | Определяет качество контента и размер маркеров |
| **5** | Лента историй | Расширяет аудиторию - не все хотят работать с картой |
| **6** | Сортировка ленты | Удобство, но не критично на старте |
| **7** | Категории историй | Помогает навигации, реализуется просто |
| **8** | Система жалоб | Важна при росте аудитории, некритична для MVP |
